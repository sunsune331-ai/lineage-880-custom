# DB 資料庫拆表 / 合併工具 使用說明

這組工具把原本一份 15MB、150,000+ 行、261 個資料表全部擠在一起的完整 SQL 匯出檔
（例如 `260813_880.sql`），拆成 `DB\tables\` 底下「一個資料表一個檔案」，方便你未來
單獨編輯、用 git diff 追蹤改動；再用合併工具把 `tables\` 底下所有檔案組回一份完整的
SQL，供 MySQL 匯入或備份使用。

拆分／合併全程用**位元組級（byte-level）**方式讀寫檔案內容，不會對內容做任何文字
編碼轉換，所以不管是正常的中文資料，還是某些欄位裡疑似編碼轉換失敗留下的亂碼位元組，
都會被原封不動保留，不會在拆分或合併過程中被悄悄改壞。

---

## 檔案結構

```
DB\
  Split-DB.bat        ← 雙擊：把完整 SQL 拆成各表檔案
  Split-DB.ps1         （拆分的實際邏輯，Split-DB.bat 會呼叫它）
  Merge-DB.bat         ← 雙擊：把各表檔案組回一份完整 SQL
  Merge-DB.ps1          （合併的實際邏輯，Merge-DB.bat 會呼叫它）
  _dump_header.txt     ← 拆分時自動擷取的檔頭（Navicat 註解、SET NAMES 等），合併時會用到
  _dump_footer.txt     ← 拆分時自動擷取的檔尾（SET FOREIGN_KEY_CHECKS = 1;），合併時會用到
  tables\
    accounts.sql
    clan_data.sql
    weapon_skill.sql
    任務獎勵屬性.sql
    ...（每個資料表一個 .sql 檔，共 261 個）
  260813_880.sql       ← 完整版 SQL（拆分的來源檔，或合併產生的輸出檔）
```

`_dump_header.txt`、`_dump_footer.txt` 是工具自己用的中繼檔，不要手動刪除或改內容
（除非你清楚自己在做什麼）；`tables\` 底下的 261 個檔案才是你平常要編輯的對象。

---

## 使用方式一：拆分（Split-DB.bat）

**什麼時候用**：手上有一份新的完整 SQL 匯出檔（例如用 Navicat 重新匯出一次資料庫），
想把它拆成各表檔案。

**怎麼做**：
1. 把新的完整 SQL 檔（檔名要是 `xxxxxx_880.sql` 這種格式）放進 `DB\` 資料夾。
2. 雙擊 `DB\Split-DB.bat`。
3. 腳本會自動找出 `DB\` 底下**最新修改時間**的那份 `*_880.sql` 當來源，印出來源檔名、
   偵測到的表數量，然後拆到 `DB\tables\`。
4. 拆完視窗會顯示「共拆出 261 個資料表」之類的訊息，按任意鍵關閉視窗。

**注意**：如果 `DB\tables\` 底下已經有檔案（表示你之前拆過、可能也手動編輯過），
腳本會先警告你，要求輸入 `yes` 才會繼續覆蓋。**如果你手動改過某個表檔案、還沒有
備份或合併保存，看到這個警告時請先按 `Ctrl+C` 取消**，不要輸入 yes，以免改過的
內容被覆蓋掉。

---

## 使用方式二：合併（Merge-DB.bat）

**什麼時候用**：在 `DB\tables\` 底下新增/修改/刪除了某些表檔案之後，想產生一份
完整的 SQL 給 MySQL 匯入，或是要做一份完整備份。

**怎麼做**：
1. 雙擊 `DB\Merge-DB.bat`。
2. 腳本會讀取 `DB\tables\` 底下所有 `.sql` 檔（不管你新增了什麼表、刪了什麼表，
   都會自動抓到最新的檔案清單，**不需要另外設定表清單**），依檔名排序組合。
3. 輸出檔名固定用「今天日期 + `_880.sql`」，例如今天執行會產生 `DB\260813_880.sql`，
   明天執行會產生 `DB\260814_880.sql`，方便你分辨每次匯出的版本。
4. 完成後印出「已合併 261 個資料表 → DB\xxxxxx_880.sql」。

**注意**：
- 表在合併輸出檔裡的順序是照**檔名字母/筆畫排序**，跟原始 Navicat 匯出時的順序不同。
  這對 MySQL 匯入沒有影響（腳本會在檔頭放 `SET FOREIGN_KEY_CHECKS = 0;`，匯入時
  不檢查外鍵順序），只是如果你用眼睛比對合併前後的檔案，表的先後順序會不一樣，
  這是正常現象、不是資料出錯。
- 如果同一天內重複執行合併，輸出檔名會相同，**會直接覆蓋前一次的合併結果**。
- **如果你當天還沒有拆分過的完整 SQL 檔名剛好跟合併輸出檔名一樣**（例如今天日期
  剛好等於原始檔案的日期），合併會把那份原始完整檔覆蓋掉。這不會造成資料遺失
  （合併出來的內容跟原始檔在資料上是等價的，只是表順序不同），但如果你想保留
  原始檔案原封不動當作對照，建議合併前先把原始檔複製一份改名備份。

## 常見情境 FAQ

**Q: 我想新增一個資料表，該怎麼做？**
在 `DB\tables\` 底下新增一個 `新表名.sql`，格式參考其他表檔案（`-- Table structure for`
註解 + `DROP TABLE IF EXISTS` + `CREATE TABLE` + `-- Records of` 註解 + `INSERT INTO` 陳述式），
存檔後下次雙擊 `Merge-DB.bat` 就會自動包含這個新表，不需要改任何腳本。

**Q: 我想刪除一個資料表，該怎麼做？**
把對應的 `DB\tables\表名.sql` 刪掉即可，下次合併就不會包含它了。

**Q: 我只是想改某幾筆資料（INSERT），要怎麼做？**
直接用文字編輯器打開對應的 `DB\tables\表名.sql`，修改裡面的 `INSERT INTO ... VALUES (...)`
那幾行即可，存檔後合併就會反映最新內容。

**Q: 表檔案的編碼／換行符可以隨便存嗎？**
不建議。原始檔案是 UTF-8（無 BOM）、Windows 換行（CRLF）。用支援 UTF-8 的編輯器
（VS Code、Notepad++ 等）開啟編輯即可，存檔時盡量維持原本的編碼與換行設定，
避免存成 BOM 或改成 Unix 換行（LF），以免跟其他表檔案不一致（雖然不影響 MySQL
匯入本身，但混用會讓 git diff 出現整檔換行符變動的雜訊）。

**Q: 兩支 .bat 需要用系統管理員權限執行嗎？**
不需要，一般權限雙擊即可。內部呼叫 PowerShell 時用了 `-ExecutionPolicy Bypass`，
只影響這一次呼叫，不會更改你電腦上的 PowerShell 全域設定。
